# Selected browser accessibility fixtures

Run `npm run test:browser:accessibility` after installing the locked Node dependencies and building the main assets. On a fresh checkout, with PHP 8.5 and the locked Composer dependencies available, run `npm run build` before any browser command: it generates the ignored Wayfinder route/action helpers as well as the main assets. The command runs 20 selected page/component checks and four pagination ownership controls. It uses existing Playwright Chromium, or an explicitly configured absolute browser executable, without downloading a browser. The existing `test:browser:ci` aggregate retains its slate/settings checks and then runs this command. The 673 Node tests and their identities remain a separate catalog.

The fixtures mount actual application components with synthetic authentication, form, API and notification boundaries. Fixture page requests are limited to each owned local origin; hot-reload sockets and service workers are disabled. They do not send real credentials, notifications or provider requests. For normal use, omit the test-only environment variables: evidence and Vite cache use a new owned temporary directory. `REVIEW_BROWSER_EXECUTABLE` may name an absolute path to a preinstalled browser; without it, the tests use existing Playwright Chromium. When supplying custom evidence paths, also set `REVIEW_BROWSER_CACHE_DIR` if you want a chosen temporary Vite cache; normal mode creates its own cache. Custom evidence paths must supply all three variables together: `REVIEW_A11Y_TRACE`, `REVIEW_A11Y_OUTCOMES` and `REVIEW_BROWSER_NETWORK_TRACE`. Pass these only to the test process or CI job, not application runtime configuration. Keep failed logs and outcome records when investigating a regression.

The selected contracts cover visible form errors associated with invalid fields, passkey-list error announcement, menus/dialogs, loading/empty/error states, tables, tabs, selected navigation and pagination. Pagination restores focus only for its still-owned interaction: a user moving focus or changing a supported filter must keep control. Terminal pages use an enabled peer button; a failed request retains its enabled initiating button. Existing request, data and disabled-control behavior is preserved.

The date-filter check establishes keyboard reachability and labeling, then uses an explicitly programmatic functional selection. Native keyboard date selection remains manual-unverified in the local test environment; it is not credited as automated keyboard-selection acceptance. The filter-supersession control uses the enabled date filter. Season and Reset intentionally remain disabled during loading and are not forced into an unsupported interaction.

Passing these 24 controls does not establish full WCAG conformance. Native date selection, manual screen-reader announcements, zoom/reflow, contrast and broader assistive-technology behavior require separately recorded assessment. The fixtures also do not establish production authentication, backend parity, delivery, running SSR or performance/capacity acceptance. Keep those outcomes separate from this selected regression catalog.
