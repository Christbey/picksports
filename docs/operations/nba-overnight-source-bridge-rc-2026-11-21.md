# NBA overnight source bridge release candidate — November 21, 2026

The clean candidate combines the verified `nba-context-v2` identity fix (`94d787a4`) with a new NBA-only source acquisition and assessment bridge. **It is not deployed. `NBA_OVERNIGHT_SOURCE_BRIDGE_ENABLED=false` by default.** No production setting, source admission, worker or automation was changed by this work. Existing NFL ingest, research, prediction, schedules and queues retain their behavior.

## Source-only contract

`nba:refresh-overnight-sources` acquires and assesses stored/provider evidence; it never calls the shared analysis job, review coordinator/runner, forecast generator or approval writer. It does not create AI work, buy an interpretation, register/enable a source, download a PDF, or repair normalized box scores. Existing manual capture/assessment commands remain available independently.

Admission requires the new flag plus existing structured-capture/research gates and approved sources. The existing canary policy still bounds the scope to at most two explicit teams with an unexpired, offset-bearing expiry. Missing, duplicate, invalid or expired scope fails before acquisition. The bridge has no force option or automatic scope renewal. It runs only in the NBA season and **23:00–07:59 America/Chicago**.

Every admitted team receives an observation, even when no game is in range. Context capture/assessment is bounded to **one eligible pregame NBA game starting within eight hours**, using the canonical event clock and both admitted teams. An empty horizon reports `team_health_only_no_upcoming_game`, not complete game research. Multiple admitted games or an unapproved/mismatched event-context source fail preflight; they are not silently truncated or auto-approved.

For a selected game, approved current summary/depth/history JSON is archived through the existing bounded capture service, then assessed directly through `GameResearchService` under the existing ordered team locks. The assessment can remain partial with projected/unconfirmed starters. A successful bridge result requires current evidence and availability, lineup, rotation and rest/travel coverage on both sides; missing coverage produces a failed run with the partial/diagnostic evidence retained. No supporting betting argument or approval is manufactured.

## Bounds, concurrency and authority

- One shared **660-second lease**, at most **24 fetch slots per run** including cache reads, existing 20-second per-fetch timeouts, 2 MiB per-response and 4 MiB retained context-packet limits. Reference expansion cannot exceed the run cap. The cap is not a claim that every source packet will fit; oversized/incomplete inputs remain failed evidence.
- The bridge installs a bounded NBA feed client only for its own execution and restores the prior client in `finally`. Every fetch rechecks the active source's NBA kind, approval, allowed host, team/event identity, current admission and overnight window. One source cannot authorize another source's fallback. Existing approved ESPN HTTP references are still upgraded to HTTPS. Normal NBA/NFL clients are unchanged.
- The NBA sync action accepts an optional strict-capture argument only for this bridge. If capture is disabled or admission expires, strict execution throws rather than falling back to legacy acquisition. Existing callers retain the original default behavior. Source changes during a request remain visible; superseded, incomplete, unmapped, revoked, stale or future-dated heads cannot become verified health.
- Successful physical UTC half-hours are deduplicated using the admitted scope, expiry, event set and producer version. A marker is reusable only while its exact team heads and current reports remain applicable. Changed heads trigger reassessment rather than suppressing work. Failures do not mark completion. Both occurrences of a fall DST hour have distinct UTC slots.
- Cached observations retain their original network time. Polling, heartbeat, retry and assessment time never freshen source evidence. No failed acquisition extends last-good validity. The `nba-context-v2` producer separates packet receipt identity from raw-content identity; distinct identical full packets preserve material identity while retaining full new provenance.

## Disabled schedule and worker isolation

The candidate schedules a unique `RefreshOvernightSources` job at **:12/:42**, from **23:12 through 07:42 Central**, only when the new flag and NBA season gate pass. Existing NBA daytime injury dispatch remains **:02/:32**, 08:00–23:00; no NFL schedule definition changes. The overnight supplement reduces the planned handoff gaps without claiming an observed service SLA.

The job uses **Redis / `nba-sources`**, never the existing NFL/default/sync queues. It has **one attempt**, a **600-second timeout**, a **720-second uniqueness lease**, and the service's global acquisition lease. A queued job rechecks the flag and runtime admission; disabling the bridge cannot revive queued source work. Request-heavy NBA work must have its own worker before activation.

`CommandHeartbeat` source **`nba_source_bridge`** records the actual acquisition/assessment result, receipt/packet/report IDs, original observations, cache provenance, coverage, skipped reasons, fetch slots and completion time. Source **`nba_source_worker`** records worker completion, queue wait and duration, or terminal failure. A generic worker success, empty-horizon skip or completed-slot skip is not proof of newly fetched complete team data. Inspect the bridge result and verified receipts together.

## Verification

**320 tests / 2,097 assertions pass on SQLite and disposable MySQL 8.4.6.** Coverage includes disabled/no-write execution, read-only dry runs, completed-slot idempotency and head invalidation, raw full-context reuse, changed-content invalidation, two-sided assessment, no-game health, scope/source revocation, acquisition overtaking, expiry during a request, stale cached timestamps, approved HTTP upgrades, source-specific fallback denial, request caps, partial contexts, dedicated worker success/failure, normal boundaries, both DST transitions, and existing NBA/NFL/API/scheduler/migration guards. Tests assert zero AI work/generations and zero analysis dispatch, even when manual NBA review capability is enabled. Scoped Pint and whitespace checks pass. No API/frontend contract or migration is added. The disposable database/server/data were removed.

These are controlled tests with fake provider responses and clocks. They do **not** certify a live overnight provider/worker cycle. The prior production audit found no overnight injury dispatch or context/assessment bridge; the new candidate has not changed that live state. The existing two-team expiry was not renewed. No live source or OpenAI request was made for this candidate.
