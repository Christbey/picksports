# Sports asset and ESPN egress controls

The November 25 readiness candidate refuses asset mirroring unless `SPORTS_ASSETS_ALLOWED_HOSTS` contains the exact lowercase provider hostname. The default is empty. `SPORTS_ASSETS_MIRROR=false` remains the default. Refusal preserves the original source URL; it does not replace the model value with a nonexistent object path. No production configuration or provider inventory was changed during this work.

Before enabling mirroring, an operator must inspect authorized stored/provider asset contracts, establish each actual hostname and its ownership, and add only those exact names as a comma-separated environment value. Do not copy synthetic test hosts, admit wildcards, or add an unreviewed redirect destination just to suppress a refusal. Rebuild the deployment configuration cache through the normal release procedure. Confirm supported raster formats and storage/CDN Content-Type behavior in staging. Existing SVG, HTTP, explicit-port, oversized or otherwise unsupported assets remain remote references rather than becoming mirrored objects. A browser consuming an original remote URL is outside this server-fetch policy.

Both asset and BaseEspnService reference requests use `ApprovedHostGet`: HTTPS only, no credentials, explicit ports, fragments or IP literals; every redirect is admitted again, at most three redirects, no implicit proxies, strict TLS verification, and all DNS answers must be public. The selected validated address is pinned with cURL while retaining the original TLS hostname. The actual wire request URI is revalidated after request middleware. DNS is checked again on retries and hops. IPv4-mapped/transitional/NAT64 and private/reserved addresses are refused. Failure does not fall back to an unpinned transport.

ESPN defaults admit only the exact hosts already represented by configured API bases: `site.api.espn.com`, `sports.core.api.espn.com`, `cdn.espn.com`, and `site.web.api.espn.com`. Historical HTTP references to these admitted hosts are upgraded locally to HTTPS before sending or cache lookup. Other origins need explicit reviewed configuration changes. No live compatibility probe was performed.

Decoded response writes are capped before growing the sink (assets five MiB, ESPN twenty MiB by default; absolute configurable transport maximum fifty MiB). Asset acceptance additionally requires matching raster magic and Content-Type for PNG/JPEG/GIF/WebP, bounded dimensions (4096 default), and a safe raster extension. A false storage write is a failure. These are content checks, not an antivirus or complete image-decoder audit. Existing objects reused at the same path are not revalidated or refreshed automatically.

Per-attempt connect/request timeouts are bounded by a forty-second elapsed budget across redirects and retries. Native synchronous DNS resolution cannot be interrupted by this application deadline; do not describe forty seconds as a hard total wall-clock guarantee. Resolver failures remain closed. Transfer tests use synthetic DNS/wire boundaries or Laravel HTTP fakes; none contact a provider or internal destination. Curl configuration is built/released in a regression without executing a socket request.

Safe diagnostics record sport/type/status/exception class, not provider URLs or raw exception messages. Shared ResearchDocumentStore and official NFL ingestion now reuse protected single-hop fetches with their own exact-source/team redirect rules and 250KB/3MB budgets. Research uses one fifteen-second attempt per hop, preserves final URL receipts/304/XML protections, and has no raster restriction. Operator-attested historical timestamps and transactions opened before network fetching remain separate outstanding boundaries recorded in the outbound review. This change does not certify all outbound clients or production configuration.
