# Existing ML archive storage and training reports

`ModelArtifactRegistry::archiveExisting` relocates or materializes stored archive bytes; it does not retire an artifact or change its scientific approval. Current persisted owner and storage headers are checked before IO. Dirty or stale callers must refresh rather than reuse a cached training-run relation. Unsupported ownership is a refusal, never authority to invalidate another current row.

For qualified MLB tabular artifacts, an already canonical archive is materialized and checked against its protected SHA and byte length without uploading again or persisting its cache path. The returned model may carry a checked cache path in memory. The original training report accepts matching protected bytes only; reading or attaching that same report performs no database descriptor or original-run rewrite. A different rolling report requires a separate supported descriptor protocol and remains refused.

A qualified legacy pointer shape stages the exact original archive outside the database transaction. Commit rechecks current source, cohort, predetermined training owner and artifact, then updates only storage pointers. Cancelled saves roll back SQL. Original ModelRun metadata, path, hash and proof remain unchanged. A staged object can remain after refusal: retain it as an auditable orphan for reviewed cleanup; this repair does not delete it or activate a cleanup policy. Logical archive/report bounds reuse the existing 256 MiB / 2 MiB policies.

The archive command returns failure for ownership/admission refusals without changing status. Existing current-owner nonMLB missing-file invalidation behavior is retained, with current-owner checks and atomic pointer/run persistence. Fresh run metadata is merged after IO; a stale cached relation cannot overwrite unrelated current metadata.
