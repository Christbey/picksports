# CFB kickoff evidence and operations

Reviewed November 27, 2026. This guide describes the accepted private candidate, not deployed production behavior. The candidate adds migration `2026_11_27_210000_add_cfb_kickoff_observation.php`; the complete candidate migration ledger currently contains 382 entries. Verify the actual release manifest and migration status rather than treating this count as permanent.

CFB kickoff is admitted from a bounded, current provider observation tied to the current provider event ID and stored UTC date/time. An explicit offset or `Z` is required. A genuine UTC midnight is valid. Legacy date/time fields alone, including midnight-like values, do not prove kickoff. No historical clock is backfilled or inferred from a default hour.

`kickoff_observation` is a current descriptor, not immutable point-in-time evidence or an observation-time audit log. It records the provider source and original bounded date payload with explicit time validity/TBD information. Schedule, scoreboard and verified summary writes update this descriptor with their clock fields. A same-event verified summary that says time is TBD invalidates the current cutoff and clears the linked canonical Event start; transport and identity failures do not erase previously admitted facts.

Unknown or invalid kickoff withholds operations requiring an exact cutoff, new canonical evaluation/publication and pregame prop baselines. Descriptive calendar inventory and completed results remain usable where their consumer does not require an exact start. Existing historical evaluations and baseline records are retained. Live actual values, including zero, remain actual observations; an unknown kickoff cannot supply a pregame prior or line comparison.

The prop calendar reads bounded scalar headers before decoding observations. Candidate and date limits are deliberate refusal boundaries, not permission to silently truncate results. Baselines are tied to the exact game, provider identity, admitted cutoff and current canonical-event binding; a changed or removed binding requires recomputation rather than relabeling an old baseline.

Before activation, drain old writers and workers, rehearse the exact release upgrade on an isolated restored database, apply the observation migration, and start only workers running the same release. Verify both API rendering and canonical cutoff behavior. Do not mix old writers that change clock carriers without the new observation contract with consumers expecting that contract. Production upgrade, rollback and recovery acceptance are still open.

To resolve a particular unknown game, first verify its internal game ID, provider event identity, environment and the source of its kickoff. Use the existing metadata verification workflow on that bounded target. The command is `espn:sync-cfb-pregame-metadata` with `--game-id`, `--season`, `--days-forward` and `--limit` options; it performs provider IO and database writes and is not a read-only diagnostic. Never pass an empty or coerced game ID. Inspect help and the exact deployed command before execution. A failed verification must remain unavailable rather than becoming an assumed clock. No provider refresh is authorized merely by an ordinary sports-analysis question.

The broader CFB-only date-window, explicit-start filter and pregame-horizon follow-up is now privately accepted with separate portable and native evidence. Unknown clocks retain raw-date calendar inventory but cannot qualify an exact before-start filter. Explicit unknown games are verified before horizon exclusion, then the confirmed cutoff is checked again. Invalid explicit IDs refuse rather than broadening selection. Candidate limits and failed or deferred verification return non-success. A fresh complete combined test checkpoint, fleet behavior, runtime capacity and historical source availability remain unverified. See the production-readiness scope and source-bound CFB receipts for the controlling status.


The privately reviewed CFB cutover report checks scoped scheduled/delayed games even when their old carriers cannot place them after the cutover. Unknown current kickoff, missing or wrong Event binding, and a mismatched current instant hold readiness. The Event wall clock uses the application timezone, matching the identity synchronizer; UTC game carriers remain UTC. The scan uses bounded scalar observations and refuses beyond 10,000 candidates or 1,000 hold IDs. Season/week filters, completed history and the existing empty-scope diagnostic remain distinct. Use `--fail-on-not-ready` for a nonzero hold status; an empty diagnostic is not deployment, model-performance or betting approval.
