# MLB output and period registration boundaries

A pregame capture marker proves when a baseline input was captured. It does not prove that an inference model ran. `ShadowModelOutputRecorder` accepts no new MLB execution rows from serialized `shadow_inference` or calibration dictionaries. The supported tabular output writer remains `MlbInferenceOutputCommit`, with its separate owned source, target, artifact and role admission.

The generic recorder may return an already stored, identity-matching MLB output for historical audit and idempotence. It does not change that row, its status, the training artifact or promotion status. Returning historical bookkeeping supplies neither current inference authority nor approval. Downstream decision eligibility still requires its current source and market gates. Feedback and settlement tests seed explicit retained database facts; they do not certify a new execution.

For other sports, the recorder retains the existing private bookkeeping contract, including NFL's in-memory audit metadata and generation time. It classifies the persisted snapshot with a current locking read, then locks all planned artifact UUID leaves in sorted order inside one connection transaction. It preserves the caller's context return order. This acquires no Event, Game or source-range locks and no late training-run parent lock. It is not a complete inference proof or a distributed/fleet guarantee. Finite-number admission, all model observers, cached-run lifecycle and Git/version-file IO in `ModelRunRecorder` remain separate concerns; no universal output atomicity or all-IO bound is claimed.

## New period registration is unavailable

`MlbPeriodModelRunRegistrar` refuses new registration until a reviewed period source-proof and selection protocol exists. The current selector's qualified MLB protocol supports tabular artifacts, not period training. Committing a generic period run, artifact and stored files before that known selector refusal is unsafe. Registration now refuses before those mutations.

This does not disable the period feature setting, retune model parameters, rename stored artifacts or change retained period reads. Their existing numeric-format, observed-start declaration and read-only 32 MiB materialization policy remain. It also does not implement a qualified period-training positive or repair the separate retained-period final-output protocol.

The historical feature builder correctly labels its reconstructed rows `pregame_safe=false` and `availability_status=reconstructed_now`. Preserve those facts. Worker declarations, a numeric format marker and CSV fields claiming availability cannot upgrade them into source proof.

The registrar's refusal preflight reads at most 2 MiB plus one guard byte for manifest JSON, with 50,000 lexical tokens and depth 24 before decoding. Its negative CSV probe is limited to 64 KiB plus one guard byte, 128 columns and the first 128 rows. These are refusal resource bounds, not a supported period dataset capacity or a complete availability validator. Passing the probe still reaches an explicit capability refusal. Logical reads are bounded; filesystem races, blocking IO, hard RSS and production artifact compatibility are not certified by these checks.

A future supported period registration path needs a bounded, versioned proof linking actual immutable pregame captures to subsequently observed targets, owned current-source admission, a period-specific selection contract and failure-safe storage/SQL publication. No flag backfill, training run or approval should be created to simulate that missing contract.

The default `mlb:train-period-models` command now reports this unavailable capability before historical source scanning, CSV writes or a child process. A manual default invocation or a previously queued default job therefore fails explicitly without attempting training. The existing `--no-register` research path retains its source-availability checks; actual historical rows remain reconstructed and are refused before Python. This does not establish a supported qualified research-training dataset or repair that path's separate process environment/resource limits. Retrospective export remains a descriptive operation only.

Automatic weekly F3/F5 registration training is retired from the scheduler while that capability is unavailable. Supported MLB/NFL weekly tabular training and retained period shadow reads remain scheduled. Manual default training still returns the explicit unavailable error; `--no-register` retains its source checks. No inference feature flag, approval or model parameter is changed. The heartbeat dispatcher only queues jobs; the worker treats a nonzero command exit as failure before recording success or sending its external success heartbeat. Historical heartbeat rows are retained, not relabeled. Current heartbeat-health model checks cover Elo/team metrics, not a promise that period training is available.

Retained MLB generic bookkeeping is a read-only lookup by the current persisted snapshot header, artifact and known market identity. Mutable dictionary output values do not revalidate, refresh or replace an existing historical row. This return value is not proof of a new model execution or of the supplied value being a valid probability. New generic outputs for supported non-MLB paths retain finite/range/storage and persisted-write admission. The separately typed MLB coordinator remains the only reviewed author of new MLB execution outputs. The post-eighth private repair passed a scoped 39-test/330-assertion portable cohort; native, combined and production acceptance are separate.
