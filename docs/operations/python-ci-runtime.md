# Python CI runtime

The scientific Python CI jobs target Linux ARM64 on `ubuntu-24.04-arm` with CPython `3.12.16`. Each job creates a fresh virtual environment. The shared [runtime lock](../../ml/runtime/requirements-linux-aarch64-cp312.lock) contains the complete 34-package target closure, including test and build tools, with exact wheel hashes. It covers the combined NFL and MLB dependency graph; it is not a general lock for macOS, Windows, another Python version or x86 Linux.

Installation accepts binary wheels only and requires the recorded hashes. Dependency resolution is disabled for both the locked environment and the editable application package. Editable installation uses the pinned build tools already installed in that environment, without build isolation. `pip check` must succeed before the existing package tests or numeric interoperability fixture preparation run. No ambient system scientific packages are inherited by the new virtual environment.

The NFL interoperability lane retains its four isolated PHP contracts and 128 MiB caller limit. Both NFL and MLB package test commands remain unchanged in scope. These tests include existing small synthetic estimator fits; this workflow change does not authorize production training, model promotion or approval changes.

The lock preserves the 29 unaffected package versions and hashes, updates four packages with reported advisories, and adds Pygments required by the new pytest version. The exact 34-wheel closure has passed byte, metadata, aarch64 ELF and offline target-runtime qualification on the unchanged Ubuntu CPython 3.12.3 guest: both application packages built, `pip check` and scientific imports passed, all 154 NFL, 99 MLB and 20 runtime-contract tests passed, and retained numerical and actual Parquet loader checks passed. The package suites include tiny synthetic fits. The memory test uses the kernel-reported current-image peak, an approximate counter on Linux and retains its 128 MiB limit; it does not raise or skip that limit. This guest result does not establish hosted CPython 3.12.16 compatibility. It does not require an old private runtime manifest or private proof archive: the workflow consumes the lock directly. A future dependency change needs a fresh complete target closure, wheel/tag/hash review and qualification rather than adding an unpinned package or silently changing architecture.

The official PyPI version metadata review reported no advisories for all 34 selected versions at query time. This is a dated metadata result, not an assurance about unpublished vulnerabilities or application exploitability. The original four advisory reports remain preserved privately.

Hosted execution must still establish that the selected interpreter, native libraries and installed modules work together. The hosted Ubuntu image, system libraries, Actions service and Python distribution are not fully frozen by this package lock. This contract does not establish production worker/runtime parity or deploy a runtime.

Official references: [GitHub-hosted runner labels](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), [exact Python version selection](https://github.com/actions/setup-python/blob/main/docs/advanced-usage.md), and [available Python distributions](https://github.com/actions/python-versions/blob/main/versions-manifest.json).

The hosted interpreter is an upstream CPython build selected by `actions/setup-python`, not the guest Ubuntu distribution package with the same displayed version. Ubuntu can backport security fixes while retaining its base version. Preserve and assess the distribution revision separately. The existing guest/system interpreter and old runtime are not replaced by this CI pin. The cp312 wheel lock has the same active dependency constraints at 3.12.16, but actual hosted interpreter hashes, imports, native-library behavior and complete tests remain required.
