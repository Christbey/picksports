# Betting alert delivery

`php artisan alerts:check nfl` checks stored opportunities for a sport and can write quota/deduplication reservations and dispatch customer notifications. Omitting the sport checks all seven supported sports. This is an operational write/send command, not a read-only sports-analysis endpoint or a safe connectivity probe. In the private November27 candidate, only an omitted (null) selector checks all sports. Explicit values must normalize by trim/lowercase to one of nfl, nba, cbb, wcbb, mlb, cfb or wnba; malformed selectors, including explicit zero or empty text, fail before any service call. Audit controls executed the actual CLI with only a mocked AlertService, not the real send service.

Alert eligibility checks preferences, realtime mode, sport access, tier, delivery window, template, edge-unit thresholds and enabled channels. The service locks the user for quota/deduplication reservation. The private November27 repair confirms the actual persisted requested owner, prediction identity, key, amount and timestamp before creating delivery records or invoking notification dispatch. Cancelled, rewritten or deleted reservations roll back and fail before dispatch.

A dispatch count does not establish provider acceptance or customer receipt. A transport exception is an ambiguous outcome: retained reservations and `outcome_unknown` delivery records prevent automatic replay under the same identity. Do not delete those records or reset quota to retry a possibly delivered alert. Positive transport receipts may settle an earlier unknown outcome through the existing delivery service.

Legitimate omitted-all and normalized NFL calls remain supported. This command-only change follows and is excluded from the ninth frozen checkpoint; it is not a production deployment.
