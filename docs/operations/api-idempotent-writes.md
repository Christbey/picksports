# Atomic API idempotency receipts

Reviewed keyed local API operations reserve a durable idempotency key, then commit their business changes and completed response receipt together on the existing owned connection. Pending atomic reservations can retry their original fingerprint; unresolved legacy outcomes remain held for reconciliation. Completed responses replay without repeating the business callback. Existing expiry, optional unkeyed requests and route admission rules remain unchanged.

The private candidate pins the reservation primary key, principal, route, key hash, scope, table and connection. It stages intended response status/body, canonical headers, fingerprint, mode and timestamps before persistence observers. A cancelled save, missing receipt, changed owner/key/identity/connection or different persisted response throws inside the business transaction and rolls back its local effects. Final primary projections are bounded by the staged intended values; JSON header semantics tolerate database key/whitespace normalization. The expiration response header also comes from the staged intent.
